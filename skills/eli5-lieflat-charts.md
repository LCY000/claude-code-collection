# eli5 × lieflat-charts：兩個 skill 怎麼配合

兩個各自獨立的 skill，個別介紹 + 什麼情境該配合著用。

## eli5

**連結：** https://github.com/anthropics/claude-plugins-community/tree/main/eli5

一句話講完：`/eli5 <主題>`，把任何主題解釋給完全不懂的人聽，輸出一個**大圖示、少文字**的 HTML 解釋卡，而不是長篇文字牆。

- 整份 skill 定義只有幾行提示，沒有固定範本或圖庫，示意圖全靠 Claude 臨場發揮——彈性最高、上手最快，但畫面品質跟每次表現會浮動
- 裝完不用額外設定，馬上能用
- 適合快速搞懂一個陌生名詞、準備跟完全不懂技術的人解釋東西、幫貼文配一張一看就懂的說明圖

**適合：** 想要「秒懂」而不是「精確」的情境。

---

## lieflat-charts

**連結：** https://github.com/larashero3-dotcom/lieflat-charts

模板驅動的資料視覺化 skill，跟 eli5 是完全相反的取向：**不追求快，追求每張圖都誠實、可考究**。

- 圖表一律先從 60+ 張真實範本（Lupi Editorial 細讀系、Lupi Basics 熟悉輪廓系）裡選型，兩組都選不到才降級用 Glance 快讀系，不會自己發明新畫法
- 預設灰階（Mono）保底，只有資料語意明確時才自動切換彩色，同一份交付只能鎖定一種色彩系統
- 嚴格禁止斷軸、發光、3D 等常見的失真手法，遇到這類要求會直接拒絕並給誠實替代方案
- 除了單圖，也能做整頁報告（12 套中英文模板：年報、月報、白皮書、一頁紙等）

**適合：** 要放進論文、年報、公開發布內容的正式圖表，在意數字有沒有被誠實呈現。

## 什麼時候該配合著用

| 情境 | 怎麼處理 |
|---|---|
| 主題本身有**可比較的數字**（複利成長多快、兩個東西差多少、光速有多快） | 那張圖用 lieflat-charts 畫 |
| 主題是**純概念或機制**，沒有現成數字可畫（天空為什麼是藍的、引擎怎麼運作） | 那張圖讓 eli5 自己畫示意圖 |

判斷準則：這張圖背後有沒有一組真實數字。有 → lieflat-charts；沒有 → eli5。

## 實際案例

沒有直接拿 eli5 做過測試，但同一天用 lieflat-charts 重做了 SAGIN 論文筆記裡的 GEO/MEO/LEO 延遲長條圖：從「同色相＋透明度深淺」的示意畫法，改成範本庫裡的 F5 Tick Rows（1 格＝10 毫秒的可數刻度），資料不確定的地方（LEO 只有「< 40ms」上界）用虛線刻度誠實標示，不虛構精確值。這就是「有真實數字時該怎麼借用 lieflat-charts」的具體示範。
